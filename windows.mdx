Herdr runs natively on Windows using ConPTY and Windows process/runtime behavior rather than the Unix PTY model Herdr was originally built around. Most core workflows are fully supported. Some capabilities differ from Linux and macOS, and Windows may receive more platform-specific fixes as remaining gaps close.

## Installation

<Tabs>
  <Tab title="PowerShell (recommended)">
    Open PowerShell and run:

    ```powershell
    powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"
    ```
  </Tab>
  <Tab title="curl.exe fallback">
    If endpoint security blocks the fileless PowerShell command, open Command Prompt and run:

    ```cmd
    curl.exe -fsSLo install.cmd https://herdr.dev/install.cmd && install.cmd && del install.cmd
    ```
  </Tab>
</Tabs>

The installer stores releases under `%USERPROFILE%\.herdr\packages\standalone\releases`, puts the active versioned release directory on `PATH`, and keeps `%LOCALAPPDATA%\Programs\Herdr\bin` as a stable compatibility alias. A small number of older releases are retained so running processes do not block updates.

### Update Channels

Windows builds are available through both stable and preview channels. New installs use stable by default.

```powershell
# Switch to preview for newer, less-tested fixes
herdr channel set preview

# Switch back to stable
herdr channel set stable
```

<Warning>
  Preview provides newer fixes from `master` and may regress. Opt in only when you want that trade-off.
</Warning>

## Supported Workflows

<CardGroup cols={2}>
  <Card title="Local persistent sessions" icon="desktop">
    Sessions continue running after the client detaches or its terminal window closes. Run `herdr` again to reconnect.
  </Card>
  <Card title="Native ConPTY panes" icon="terminal">
    All pane types — PowerShell, cmd.exe, and others — run through Windows ConPTY.
  </Card>
  <Card title="Windows Terminal / PowerShell app" icon="window-maximize">
    Attach from Windows Terminal or the PowerShell app. The same Windows account can attach from ordinary and administrator terminals.
  </Card>
  <Card title="Remote attach" icon="network-wired">
    `herdr --remote` and saved SSH machines connect to Linux, macOS, and Windows hosts. Interactive setup can install or update Windows packages after confirmation.
  </Card>
  <Card title="Agent detection" icon="robot">
    Agent process-tree detection scans descendants of the pane shell, including npm/Node and Git Bash process chains. It follows Git Bash-launched agents across emulated `exec` boundaries.
  </Card>
  <Card title="System notifications and sound" icon="bell">
    System notifications and MP3 sounds are fully supported. Clicking a notification selects its originating pane and brings the terminal window forward when Windows exposes that window.
  </Card>
</CardGroup>

Additional fully supported capabilities: remote clipboard images and image-file drops, `cmd.exe` panes, native keyboard and mouse input, startup cwd and workspace labels, pane launch cwd, agent command discovery, supported agent self-report integrations, Git/worktree detection, pane screen history, and nested launch override.

### Agent Integrations on Windows

Windows integration installation currently supports Pi, OMP, Claude Code, Codex, GitHub Copilot CLI, Devin CLI, OpenCode, Kilo Code CLI, Droid, Kimi Code CLI, Qoder CLI, and Antigravity CLI. Availability is narrower than on Unix; Herdr hides or rejects integrations whose install format is not supported on Windows.

## Partial Support

| Capability | Status |
| --- | --- |
| Live cwd after shell `cd` | Partial |
| Live cwd via shell integration/OSC7 | Supported |
| Clipboard image paste to agents in local panes | Terminal/agent dependent |
| CJK IME composition anchoring | Partial |
| Prefix input-source switching | Partial (Korean IME only) |
| Kitty graphics rendering | Terminal dependent |
| Host cursor rendering | Partial |

Herdr can launch panes in the right directory and create the initial workspace from the directory where you started Herdr. After startup, the process field Herdr can inspect does not reliably track later logical `cd` changes in PowerShell. Use Herdr integrations or prompt shell integration for live cwd reporting via OSC7.

## Copy and Paste

Herdr's pane text copy works on Windows. Drag-select text inside a pane to copy through Herdr.

For text paste, use `ctrl+shift+v` in Windows Terminal. Multiline text paste is bracketed so shells and agent prompts receive it as one paste instead of submitting each line separately.

<Tip>
  Hold `shift` and right-click to use the outer terminal paste action instead of sending the click through Herdr.
</Tip>

## Remote Attach From Windows

From Windows Terminal, use the same remote command as Linux and macOS:

```powershell
herdr --remote workbox
```

The target host can run Linux, macOS, or Windows. Herdr uses the installed Windows OpenSSH client and your SSH configuration.

<Note>
  Windows OpenSSH does not use Herdr's Unix control-socket reuse. Key authentication through Windows `ssh-agent` is recommended to avoid repeated prompts during remote setup.
</Note>

## Known Caveats

### ConPTY and Cursor Rendering

Herdr relies on ConPTY for native Windows panes. The Windows terminal cursor path can expose intermediate positions while a multiplexer repaints the screen — a native cursor may flicker, jump, or briefly remain at an old position during active output. This behavior also reproduces in other native Windows terminal multiplexers, so Herdr cannot eliminate it while preserving native cursor behavior.

The default `host_cursor = "auto"` draws Herdr's cursor as terminal cell content on native Windows and WSL, keeping it steady and non-blinking. Other Linux and macOS clients continue to use the native terminal cursor.

<Accordion title="Restoring the native cursor (and IME anchor)">
  The drawn Windows cursor does not position IME composition and candidate UI. Korean, Japanese, or Chinese IME UI may appear at the wrong location. Opt back into the outer terminal cursor to restore the IME anchor:

  ```toml
  [ui]
  host_cursor = "native"
  ```

  Native mode restores the IME anchor but can reintroduce occasional cursor flicker, jumps, or stale positions during active output.
</Accordion>

### Keyboard and Mouse

Windows terminals do not all report modified keys in the same shape. Herdr preserves mouse reporting and `ctrl+j` in Windows Terminal and Alacritty on Windows. Modified keys still depend on the outer terminal reporting a distinct key event.

Windows packages include Microsoft's current app-local ConPTY runtime because the system ConPTY on older Windows 10 builds drops Kitty keyboard protocol sequences used by agents such as Kimi and Pi.

<Tip>
  Set `HERDR_WINDOWS_CONPTY=system` before starting Herdr only when diagnosing a compatibility problem with the bundled runtime.
</Tip>

### Kitty Graphics

Kitty graphics is enabled by default and depends on the outer terminal. Windows Terminal does not expose the Kitty graphics path Herdr uses. Set `kitty_graphics = false` if the outer terminal mishandles graphics output:

```toml
[terminal]
kitty_graphics = false
```

### Prefix Input-Source Switching (Korean IME)

Herdr can temporarily switch to ASCII input while prefix commands are active:

```toml
[experimental]
switch_ascii_input_source_in_prefix = true
```

<Warning>
  On Windows, support is currently limited to the Korean IME. With an IME for any other language, this setting leaves the input source unchanged.
</Warning>

## Not Supported on Windows

| Capability | Status |
| --- | --- |
| Direct terminal attach (`herdr terminal attach`) | Unsupported |
| Live server handoff | Unsupported |
| Unix file-descriptor handoff | Unsupported |
| Unix foreground process groups | Unsupported |
| Herdr clipboard image bridge in local native panes | Unsupported |
| Signed binary / SmartScreen avoidance | Unsupported |

## Plugins on Windows

Plugins support `windows` as a manifest platform in preview. GitHub install, local link, build commands, actions, events, and plugin panes are best-effort on Windows. Commands are argv commands and must be Windows-compatible; Node package shims such as `npm`, `bun`, and `node` are expected to work when they are on `PATH`, while Unix-only examples using `sh` or Bash need Windows-specific alternatives.

## Reporting Windows Issues

Include the following when filing a bug report:

- Herdr version
- Windows version
- Terminal app (Windows Terminal, Alacritty, WezTerm, etc.)
- Shell (PowerShell, cmd, etc.)
- Whether you used a named `HERDR_SESSION`
- Relevant Herdr logs from `%APPDATA%\herdr\`
- Exact steps to reproduce
